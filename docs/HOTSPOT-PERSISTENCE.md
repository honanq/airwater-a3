# 热点名称和密码反复要求输入

## 已确认的应用端原因

对比附件 `airwater-a3-main 6.zip` 与仓库基线 `ffa1321`，52 个文件内容一致。

1. `ConnectionView` 的热点名称、密码原先只是初始为空的 `@State`。原有 `DeviceKeyStore` 存的是 A3 的设备 ID/签名密钥，不是 Wi-Fi 凭据。没有热点配置持久化或启动时回填，因此 App 进程被回收、冷启动后输入为空。
2. 配网按钮调用 `bluetooth.provision(...)` 后立即清空密码。蓝牙状态不满足、SSID/密码字节长度校验失败、设备拒绝、写入错误、超时，都会使用户再次输入；清空甚至不以请求成功发出为前提。
3. 没有发现定时删除热点配置或后台自动重新发送 cmd21 的业务路径。现有源码不足以认定 A3 固件、Flash 或手机系统真的忘记 Wi-Fi 配置。

普通 SwiftUI 重绘、正常进入后台本身不代表 `@State` 一定被清除。这里明确修复的是缺少持久化与无条件清空。

## 修复后的行为

- 以根视图 `@StateObject HotspotSettings` 管理输入；设备通过 cmd21 状态 `1` 确认接受后，将**本次实际发送的快照**安全保存到独立的本机 Keychain 条目。
- 不再在点击发送后清空密码；输入校验失败、BLE 失败和重试保留当前输入。尚未被设备确认的新输入不会覆盖上一次已保存的配置。
- 保存不依赖后续 cmd22 设备 ID 查询成功；设备接受配置不代表已联网，也不保证设备端已完成非易失存储。
- 冷启动自动恢复，锁定/暂时不可读会提示并在回到前台时重试；读取失败与条目不存在分开处理，不删除旧条目。已编辑过的草稿即使被用户清空，也不会被自动回填覆盖。
- 保存失败显示提示并保留已接受的快照，可点「重试保存到本机」；该操作只重试 Keychain，不重新发送 BLE 配网。
- 「忘记本机保存的热点」需要确认，只删除本 App 的热点条目与本次草稿，不改系统热点、不清空 A3、不删除设备签名密钥。配网请求进行中禁止忘记，避免迟到的成功应答把已忘记的记录重新保存。
- 自动填入不等于自动配网；仍只有用户点配网按钮才向选中的 A3 发送 cmd21。

已输入但未发送、发送尚未确认、确认后本机保存失败且未重试就杀掉进程的新配置，不承诺下次恢复。第一次安装修复版时旧版本没有可迁移的热点记录，需要完成一次配网；显示「已安全保存在本机」后才能验收跨冷启动恢复。

## 隐私与签名

热点凭据与设备密钥使用不同 service/account。热点条目使用 `WhenUnlockedThisDeviceOnly`，`kSecAttrSynchronizable = false`；不使用明文 UserDefaults、文件备份、日志或 iCloud 同步。

固定 service/account 不足以保证跨换签读取。覆盖更新应保持实际 Bundle ID、签名后的 application identifier/App ID prefix 与 Keychain access group 一致；更换 Apple 开发者身份、侧载工具生成的新标识或卸载重装后能否访问旧条目，必须按实际 entitlement 验证。本修复不放宽 Keychain 访问权限，也不承诺跨设备迁移。不要把真实热点密码提交到仓库或诊断。

## 断线不一定要重新配网

本方案还依赖本地 DNS/HTTP/MQTT。原有会话上限是 600 秒，进入后台后运行时间也受系统限制。会话结束、App 被挂起或服务启动顺序不对，会导致不能控制，但不等于热点名称/密码已经被设备清除；这些限制本次没有改变。

热点名称/密码未变时，先用首页重新连接，或手动依次「关闭热点 → 准备本地服务 → 开启热点 → 回到 App」，开启系统热点的最大兼容性。只有首次配置、更换热点或确认设备确实无法按原凭据入网时才重新蓝牙配网。不要为一次断线先恢复出厂。

### 真机必须验收

1. 原签名身份覆盖安装，首次正常配网，看到本机保存成功；杀掉 App 再打开，热点名称与遮蔽密码自动恢复，不自动扫描或配网。
2. 非空但不足 8 字节的密码、超长 UTF-8 SSID、蓝牙断开/拒绝/超时后，输入仍在；旧已保存记录不被失败请求覆盖。
3. 发送配置 A 后把表单编辑为 B：A 被接受时只保存 A，不覆盖当前 B。cmd21 成功而 cmd22 超时/断开，下一次仍能恢复 A。
4. 锁定导致读写失败时有提示，不默默清除；解锁回前台可恢复未编辑表单。已编辑、再手动清空的草稿不会被旧值回填。
5. 保存失败时重试只写本机，不能重新控制 A3。配网在途不能忘记；确认忘记后不再恢复，不影响原 A3 网络和设备密钥。
6. 保持同一签名身份覆盖更新与改变侧载签名/Bundle ID 分开验收。保持热点凭据不变，测试会话到期及恢复服务后是否无需重新配网。

没有连接用户的 A3 或执行断电保持测试。本次修复不声称已排除固件保存失败、硬件 Flash 故障或热点兼容性问题。
